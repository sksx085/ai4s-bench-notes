# AI4S 出题工作台

运行同级的 [workbench.py](scripts/workbench.py)，使用 Python 3.9+。[本地用法](references/contract.md)列出命令与字段。

## 搭建出题骨架

阅读用户给出的研究目标和材料。用 `init` 建立题目规格、题面预览和组织方记录。任务计分或排名时加 `--scored`。依据材料填写，未确定的条件留待作者决定。

| 栏目 | 写清楚什么 |
| --- | --- |
| 问题 | 要预测、判断或设计什么。关键术语首次出现时定义。 |
| 输入 | 作答者能见到的文件、数据和公开示例，以及它们如何对应。 |
| 输出 | 要交哪些文件、填哪些字段，怎样算交齐。 |
| 约束 | 科学条件、可用资料和工具，以及实际采用的时间或资源限制。 |
| 精度 | 单位、提交位数和舍入方式。若已知，说明参考值来自何处、报告有多精细。 |
| 评分（按需） | 主指标、逐题误差如何汇总，以及实际采用的判分容差。 |

## 精简已有题面

1. 读原题、公开材料、提交校验和评分器，把作答者需要知道的内容登记到规格。旧 Markdown 可用 `init --legacy-brief` 接入。
2. 将需要改写的栏写成短文 JSON，用 `simplify` 生成五栏新稿。先删重复叙述和解题暗示。术语需要定义就在「问题」加一句，数据关系需要解释就在「输入」举例，提交容易出错就在「输出」放一条格式示例。额外背景可用 `--add background`。
3. 对照原题和新稿，核实条件、公开数据、行列覆盖、提交精度和评分口径等是否一致。`simplify` 保留结构化契约，短文是否遗漏要求仍要逐项复核。需要保存可继续核查的精简规格时用 `--format spec`。

科学判断查[原始证据](references/science.md)。需要核对题包时用 `audit`、`check-submission` 或 `freeze`。只有在用户要求评分复放、独立评阅或模拟考试时才执行。参考答案和组织方记录单独保存。
